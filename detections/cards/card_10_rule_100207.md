## 1. Detection Logic in Plain Language
Detects Windows Security Event ID 1102 (`The audit log was cleared`, parent rule `60117`) or Windows System Event ID 104 (`The Log file was cleared`, parent rule `60000/60001`).

## 2. Expected False Positives
- Authorized system administrator clearing logs during a documented maintenance/decommissioning procedure.

## 3. Verification Tests (Attack & Benign)
- **Attack Trigger Command:**
  ```text
  wevtutil cl Security
  ```
- **Benign Activity Test (Must NOT Fire):**
  ```text
  wevtutil qe Security /c:1 /f:text (queries 1 event without clearing the log).
  ```

## 4. L1 Analyst Triage Steps
1. Identify the account that cleared the log (`data.win.eventdata.subjectUserName` / `subjectDomainName`) and the log channel (`Security` or `System`).
2. Immediately query Wazuh Indexer for all events from that host recorded BEFORE the log-clear timestamp (since Wazuh already ingested them in real time before local eviction!).
3. Look for preceding high-severity alerts (`100200`, `100005`, `100201`, `100206`) that the intruder was attempting to cover up.
4. Treat an unplanned log clear on a production/lab endpoint as high-confidence evidence of active intrusion or defense impairment.

## 5. Escalation Path
- Escalate to L2/IR Lead within 30 minutes (P2), or P1 if preceded by execution/persistence alerts.
- **Six-Field Escalation Call Required:** *Who, What, When, Where, Evidence, Need.*
