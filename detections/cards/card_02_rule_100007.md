## 1. Detection Logic in Plain Language
Two-stage correlation: Rule `100007` fires when 5 failed Windows logons (Event 4625, parent rule `60122`) occur for the same `win.eventdata.targetUserName` within 120 seconds. Correlation Rule `100200` fires at Level 13 when a successful logon (Event 4624, parent rules `60106/60118/60119/100204`) occurs for that same `win.eventdata.targetUserName` within 300 seconds of `100007`.

## 2. Expected False Positives
- An employee who mistypes their password 5 times at the Windows lock screen and then enters the correct password on the 6th attempt.

## 3. Verification Tests (Attack & Benign)
- **Attack Trigger Command:**
  ```text
  5 failed password attempts for user `soc`, followed by 1 successful logon within 5 minutes.
  ```
- **Benign Activity Test (Must NOT Fire):**
  ```text
  1 single mistyped password (4625) followed by a successful logon (4624) — stays below the `frequency=5` threshold.
  ```

## 4. L1 Analyst Triage Steps
1. Confirm `data.win.eventdata.targetUserName`, `data.win.eventdata.logonType` (Type 2 interactive, Type 3 network, Type 10 RDP), and `data.win.eventdata.ipAddress`.
2. Query Wazuh for all 4625 events in the preceding 5 minutes to count total failures and check if multiple accounts were targeted (password spraying vs. single-account brute force).
3. Check post-logon activity by `targetUserName` on the destination host (`100005` PowerShell, `100201` LSASS, `100206` Run key).
4. If `ipAddress` is external or non-management, or if suspicious commands follow the logon, treat as a confirmed account compromise (P1).

## 5. Escalation Path
- Immediate P1 escalation (within 15 minutes) to L2/IR Lead using the six-field structure whenever Rule 100200 fires from a remote IP or is followed by privileged commands.
- **Six-Field Escalation Call Required:** *Who, What, When, Where, Evidence, Need.*
