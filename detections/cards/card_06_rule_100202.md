## 1. Detection Logic in Plain Language
Detects write or attribute-change operations recorded by `auditd` with key `ssh_authorized_keys` (or `ssh`) targeting any file ending in `authorized_keys`, excluding normal reads by `/usr/sbin/sshd`.

## 2. Expected False Positives
- Authorized administrator adding a new public key under an approved access request ticket.

## 3. Verification Tests (Attack & Benign)
- **Attack Trigger Command:**
  ```text
  echo "ssh-rsa AAAA test" | sudo tee -a /home/kali/.ssh/authorized_keys
  ```
- **Benign Activity Test (Must NOT Fire):**
  ```text
  ssh -i ~/.ssh/soclab_ed25519 soc@192.168.99.40 whoami (normal `sshd` read of `authorized_keys` does not trigger a write watch).
  ```

## 4. L1 Analyst Triage Steps
1. Check `data.audit.file.name` to identify which user account's `authorized_keys` file was modified (`/home/kali/.ssh/authorized_keys`, `/home/soc/.ssh/authorized_keys`, `/root/.ssh/authorized_keys`).
2. Identify the modifying process (`data.audit.exe`) and login user (`data.audit.auid`).
3. Diff or inspect the target `authorized_keys` file to identify the newly appended public key comment and fingerprint.
4. If unapproved, preserve a copy of the modified `authorized_keys` file with its SHA-256 hash, remove the rogue key, and audit recent SSH logins for that user.
